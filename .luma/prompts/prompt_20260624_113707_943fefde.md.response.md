### Step 1: Verify Telegram Warning Label (Option C)
- Send your location or `/check` to the Telegram bot to trigger a rain prediction for an area where rain is expected.
- **Expected Result:** If the radar data is missing timestamps (gap > 20 mins) or the data is old (age > 30 mins), the bot should reply with the warning `⚠️ ข้อมูลขาดช่วง (ความแม่นยำต่ำ)` appended to the rain summary. If data is fresh and consecutive, the warning should not appear.

### Step 2: Verify Polled Static Frames Architecture & Caching (Option A)
**เป้าหมาย:** ตรวจสอบว่าระบบสามารถดูดภาพนิ่ง (Static) ในทุกๆ 5 นาที และเอามาต่อกันเป็นเฟรมเก็บไว้ใน Local/Firestore ได้ถูกต้อง

**วิธีทดสอบ (Step-by-Step):**
1. เปิด Terminal และเข้าไปที่โฟลเดอร์ `backend/` จากนั้นรัน Local Server ด้วยคำสั่ง:
   ```bash
   npm run dev หรือ uvicorn app.main:app --reload
   ```
2. ทำการยิง API หรือเรียก Cron job ของ Backend ตรงๆ เพื่อจำลองการทำงานทุกๆ 5 นาที:
   ```bash
   curl -X POST http://localhost:8000/worker/fetch-tmd-radar \
        -H "x-worker-secret: default_secret_for_local_testing"
   ```
3. สังเกตใน Terminal (Log) ให้สังเกตข้อความที่พิมพ์ออกมา:
   - **กรณีสำเร็จ:** `Updated Firestore radar cache for kkn240 with [1-6] frames, latest ts 1700000000`
   - **ความหมาย:** หมายความว่าระบบสามารถโหลดภาพใหม่มาได้ สกัดเวลาด้วย OCR สำเร็จ และนำมาเก็บใน Array ของ `frames` สำเร็จ
4. ลองรันคำสั่ง `curl` ในข้อ 2 ซ้ำอีกครั้งทันที:
   - **กรณีสำเร็จ:** `[kkn240] Image unchanged (ts 1700000000). Skipping.`
   - **ความหมาย:** ระบบจะรู้ว่าภาพเป็น timestamp เดิม และข้ามการประมวลผลไป เพื่อประหยัดโควต้า

### Step 3: Verify GIF Fallback Logic & Cooldown (Option B)
**เป้าหมาย:** ตรวจสอบว่า ถ้าระบบไม่ได้ภาพนิ่งใหม่ๆ มานานเกิน 60 นาที ระบบจะยอมโหลด Loop GIF มาแกะเฟรมหรือไม่ และถ้าพยายามโหลดแล้ว จะต้องติด Cooldown 30 นาที

**วิธีทดสอบ (Step-by-Step):**
1. **เตรียมสภาพแวดล้อม (จำลองว่าภาพนิ่งตาย):**
   - ให้เปิดไฟล์ `backend/app/services/tmd_radar_processor.py` ชั่วคราว
   - มองหาบรรทัด `url = self.config.static_image_url` 
   - แก้เป็น `url = "http://localhost:9999/broken.jpg"` ชั่วคราว เพื่อบังคับให้โหลดภาพนิ่งไม่สำเร็จ
2. ไปที่ Terminal ที่รัน Server ค้างไว้ แล้วใช้คำสั่ง `curl` สั่งให้ระบบเช็คเรดาร์:
   ```bash
   curl -X POST http://localhost:8000/worker/fetch-tmd-radar \
        -H "x-worker-secret: default_secret_for_local_testing"
   ```
3. **ผลลัพธ์ที่คาดหวังครั้งแรก (Fallback ทำงาน):**
   - Log จะขึ้นเตือนว่า: `[kkn240] GIF fallback triggered: Static dead for Xm` หรือ `Cache has <2 frames`
   - Log จะตามด้วยการโหลด GIF: `[kkn240] Executing GIF fallback recovery...`
   - สุดท้ายจะแกะเฟรมได้: `GIF fallback found 6 frames` (และเอาไปใช้งานแทน)
4. **ทดสอบระบบ Cooldown:**
   - รันคำสั่ง `curl` ในข้อ 2 ซ้ำอีกครั้งทันที
   - **ผลลัพธ์ที่คาดหวัง:** ต้อง **ไม่มี** ข้อความ `Executing GIF fallback recovery...` ปรากฏขึ้นอีก เนื่องจากเพิ่งดึง GIF ไปเมื่อสักครู่ ระบบจะต้องเข้าสู่ Cooldown 30 นาที (1800 วินาที)
5. **ทำความสะอาด (Clean up):**
   - ลบ `http://localhost:9999/broken.jpg` ออกและเปลี่ยนกลับเป็น `self.config.static_image_url` เหมือนเดิม
