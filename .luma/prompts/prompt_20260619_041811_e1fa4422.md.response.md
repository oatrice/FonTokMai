- Step 1: Open a terminal and navigate to the backend folder: `cd backend`
- Step 2: Activate your Python virtual environment to make `uvicorn` available. Run `source .venv/bin/activate` (or `source venv/bin/activate` if your folder is named venv).
- Step 3: Start the local FastAPI server by running `uvicorn app.main:app --reload --port 8000`.
- Step 4: In a new terminal, run the fetch-radar worker endpoint using curl: `WORKER_SECRET=$(grep WORKER_SECRET .env | cut -d'=' -f2) && curl -X POST http://localhost:8000/worker/fetch-tmd-radar -H "x-worker-secret: $WORKER_SECRET"`
- Step 5: Verify that the console logs in your first terminal show `Updated Firestore radar cache for kkn120 with ts ...` and no errors related to GIF fetching.
- Step 6: Verify the database schema migration locally in Firestore. Go to the [Firebase Console -> Firestore](https://console.firebase.google.com/project/fonmayang/firestore).
- Step 7: Open the `radar_latest_cache` collection and click on a station document (e.g., `skn240`). 
- Step 8: Ensure that `url_t` and `url_t_minus_1` exist and contain valid image paths. Confirm that the data updates correctly and doesn't write to the old `radar_cache` collection anymore.
- Expected Result: The local server successfully executes the rain check routine. The Firestore database documents in `radar_latest_cache` show the correct values for `url_t` and `url_t_minus_1`.
