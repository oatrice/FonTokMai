## Part 1: `check_public_access.sh` — Cloud Run IAM Audit

### Prerequisites
- `gcloud` CLI authenticated
- `jq` installed (`brew install jq`)

### Step 1: Syntax check + help
```bash
cd backend/scripts
chmod +x check_public_access.sh
bash -n check_public_access.sh && echo "Syntax OK"
./check_public_access.sh --help
```
**Expected:** "Syntax OK" + usage text with all flags listed (`--project`, `--region`, `--service`, `--expect`, `--quiet`)

### Step 2: Full audit (all services)
```bash
./check_public_access.sh --project fonmayang --region asia-southeast1
```
**Expected:** Each service shows `🔒 PRIVATE` or `🌐 PUBLIC`, summary counts correct, exit code `0`

### Step 3: Single service check
```bash
./check_public_access.sh --service fonmayang-backend
```
**Expected:** Only 1 service row shown, no "Fetching list" message

### Step 4: `--expect private` (pass)
```bash
./check_public_access.sh --expect private; echo "Exit: $?"
```
**Expected:** Exit `0`, no mismatch warnings

### Step 5: `--expect public` (fail)
```bash
./check_public_access.sh --expect public; echo "Exit: $?"
```
**Expected:** Exit `1`, each service shows `⚠️  UNEXPECTED`, final line `❌ Audit FAILED`

### Step 6: `--quiet` mode (CI)
```bash
./check_public_access.sh --quiet --expect private; echo "Exit: $?"
```
**Expected:** Zero output lines, exit `0`

### Step 7: Nonexistent service → error handling
```bash
./check_public_access.sh --service nonexistent-xyz-service; echo "Exit: $?"
```
**Expected:** `❓  ERROR   nonexistent-xyz-service`, exit `2`, summary line `⚠️  Audit completed with 1 error(s)`

## Part 2: Issue #121 — Parametric Mock Scenario System

### Prerequisites
- Telegram bot รันอยู่ (local `uvicorn` หรือ deployed)
- มีตำแหน่ง location บันทึกไว้ใน bot
- เป็น `DEVELOPER_CHAT_IDS` member

---

### Step 1: ทดสอบ `/devmock help`
ส่งข้อความใน Telegram:
```
/devmock help
```
**Expected:** Bot ตอบ help message ที่มีทุก command รวมถึง:
- โหมดพื้นฐาน: `rain`, `storm`, `clear`, `error`, `off`
- โหมด Parametric: `/devmock scenario <params>`
- ตาราง parameters: `rain_in`, `rain_stopping`, `no_rain`, `dbz`, `wind`, `wind_dir`, `growth`, `clusters`
- ตัวอย่าง commands

---

### Step 2: ทดสอบ `/devmock scenario` ไม่มี params
```
/devmock scenario
```
**Expected:** Bot ตอบ error แจ้งให้ระบุพารามิเตอร์ พร้อมตัวอย่าง ไม่ crash

---

### Step 3: ทดสอบฝนจะมาใน 20 นาที
```
/devmock scenario rain_in:20 dbz:40 wind:60 wind_dir:N
```
**Expected:**
1. Bot ตอบ summary:
   ```
   🛠️ [DEV MOCK] Scenario จำลอง:
   🕐 ฝนจะมาใน 20 นาที
   📡 dBZ: 40
   💨 ลม: 60 km/h จากทิศ N
   ⏳ กำลังสร้างแจ้งเตือน...
   ```
2. Bot ส่ง alert message พยากรณ์ฝน (ข้อความหลัก)
3. Bot ส่งภาพ **4 รูป** ตามลำดับ:
   - `radar_latest.png` — ภาพ radar static
   - `rain_timeline.png` — กราฟ timeline
   - `radar_tracking.png` — tracking image พร้อม arrow ชี้ทิศเมฆ
   - `radar_multiframe.png` — **ใหม่** ภาพ multi-frame strip

---

### Step 4: ตรวจ `radar_multiframe.png` โดยละเอียด
ดูภาพที่ได้จาก Step 3:

**Expected layout (horizontal strip):**
- มี columns เรียงซ้าย→ขวา (เก่า→ใหม่), จำนวน = จำนวน frames ที่ cache ไว้ (2–6)
- **NOW panel** (ขวาสุด): มี border น้ำเงิน, timestamp ขึ้นต้นด้วย "NOW"
- แต่ละ panel มี:
  - thumbnail 200×200 px ของ radar รอบ user location
  - วงกลมสี + arrow สีเหลืองแสดง cluster position
  - user pin (วงแหวนขาว + cross น้ำเงิน) ตรงกลาง
  - dBZ label สีตรง scale (เขียว/เหลือง/ส้ม/แดง/ม่วง)
  - growth/decay % สีเขียว (+) หรือสีแดง (-)

---

### Step 5: ทดสอบฝนกำลังจะหยุด
```
/devmock scenario rain_stopping:10 dbz:30
```
**Expected:**
1. Summary แสดง `🌤 ฝนจะหยุดใน 10 นาที`
2. Alert message: ข้อความบอกว่าฝนกำลังตกอยู่และจะหยุดใน ~10 นาที (eta_min = -10, negative = ฝนอยู่แล้ว)
3. ภาพ tracking: cluster dot อยู่ตรงตำแหน่ง user (ไม่ใช่ห่างออกไป)

---

### Step 6: ทดสอบไม่มีฝน (wind only)
```
/devmock scenario no_rain wind:45 wind_dir:SE
```
**Expected:**
1. Summary แสดง `☀️ ไม่มีฝน` + `💨 ลม: 45 km/h จากทิศ SE`
2. Alert message: ไม่มีฝน / ท้องฟ้าแจ่มใส
3. ภาพ `radar_tracking.png` ไม่มี cluster dot (ไม่มีเมฆ)
4. ภาพ `radar_multiframe.png` ไม่มี cluster circles (no clouds)

---

### Step 7: ทดสอบ multiple clusters + growth
```
/devmock scenario rain_in:5 dbz:55 growth:0.3 clusters:3
```
**Expected:**
1. Summary แสดง `☁️ เมฆ: 3 ก้อน` + `📈 Growth: +0.3`
2. ใน `radar_tracking.png`: มี 3 วงกลม (clusters) ที่แตกต่างกัน
3. Alert message: intensity สูง (dBZ 55+ = ฝนหนักมาก/พายุ)

---

### Step 8: ทดสอบ `/devmock off` หลังทดสอบ
```

```
**Expected:**

---

### Step 9: ตรวจสอบ `/rain tmd-radar` โดยตรง
```
/rain tmd-radar
```

**Expected:** ได้รับภาพ `radar_multiframe.png` พร้อมกับภาพอื่นๆ ปกติ (ไม่ใช่แค่ mock mode — ภาพนี้ส่งทุกครั้งที่มี 2+ frames)

## Edge Cases

| Scenario | Command | Expected |
|---|---|---|
| `wind_dir` ไม่รู้จัก | `wind_dir:XYZ` | ใช้ default N (0°) |
| `dbz` เกิน 75 | `dbz:999` | clamp เป็น 75 |
| `dbz` ต่ำกว่า 15 | `dbz:0` | clamp เป็น 15 |
| `clusters` > 5 | `clusters:99` | clamp เป็น 5 |
| frame เดียว (cold start) | ส่งไม่นานหลัง deploy | `radar_multiframe.png` ไม่ส่ง (None), ภาพอื่นยังส่งปกติ |

| Scenario | Command | Expected |
