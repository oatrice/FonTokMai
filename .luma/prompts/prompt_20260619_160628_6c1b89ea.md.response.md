# Manual Verification Guide

### 1. Verify GitHub Actions / GitLab CI Path-based Filters
- **Step 1:** Create a test branch and push changes *only* to a file under the `backend/` directory (e.g., add a comment to `backend/main.py`).
- **Step 2:** Observe the CI/CD pipeline run.
- **Expected Result:** The `deploy_cloud_run` job should be triggered (after tests pass), but the `deploy_emsc_worker` job should be skipped.
- **Step 3:** Push changes *only* to a file under `emsc_worker/`.
- **Expected Result:** The `deploy_emsc_worker` job should be triggered, but the `deploy_cloud_run` job should be skipped.

### 2. Verify Weather Manager (HQ Image Rendering & Disabled GIFs)
- **Step 1:** Start the FastAPI application locally.
- **Step 2:** Perform a manual rain prediction request for a location with active radar coverage (e.g., Nong Khai `lat=17.8785&lng=102.7420`) using `curl`:
  ```bash
  curl "http://localhost:8000/api/v1/weather/predict?lat=17.8785&lng=102.7420"
  ```
- **Expected Result:** The response should return `200 OK` with JSON fields:
  - `"radar_gif_bytes": null`
  - `"radar_hq_gif_bytes": null`
  - `"radar_static_bytes"` containing a non-empty base64 or string value.
  - No `RuntimeWarning` or `NameError` warnings in the server logs.

### 3. Verify Telegram /worker/handle-rain Endpoint (Auth & Integration)
- **Step 1:** Call the worker handler endpoint locally without authorization:
  ```bash
  curl -X POST "http://localhost:8000/worker/handle-rain" \
       -H "Content-Type: application/json" \
       -d '{"chat_id": 99999, "command": "/rain"}'
  ```
- **Expected Result:** The API returns `401 Unauthorized`.
- **Step 2:** Call the endpoint with the correct `X-Worker-Secret` header:
  ```bash
  curl -X POST "http://localhost:8000/worker/handle-rain" \
       -H "Content-Type: application/json" \
       -H "X-Worker-Secret: WORKER_SECRET" \
       -d '{"chat_id": 99999, "command": "/rain"}'
  ```
- **Expected Result:** The API returns `200 OK` with `{"status": "ok"}`.

### 4. Run the E2E Test Suite locally
- **Step 1:** Navigate to the backend directory and activate the virtual environment:
  ```bash
  cd backend
  source .venv/bin/activate
  ```
- **Step 2:** Execute pytest targeting all the new E2E test suites:
  ```bash
  pytest tests/test_e2e_*.py tests/test_tmd_radar_e2e.py -v
  ```
- **Expected Result:** All tests should execute successfully and pass (`100% passed`), confirming that mocks prevent any real GCP/Telegram API calls and the logic functions correctly.
