# Manual Verification Guide

## Overview
Changes in this review touch: TMD radar bounding box calibration, a missing `import os` fix, a new bounds unit test, and CI/CD `CRON_SECRET` injection.

---

## Step 1: Verify `import os` Fix (weather_manager.py)

**Goal**: Confirm that TMD radar no longer crashes with `name 'os' is not defined`.

1. Start the local server (already running via `uvicorn`).
2. Send a weather prediction request for a Nong Khai coordinate:
   ```bash
   curl "http://localhost:8000/api/v1/weather/predict?lat=17.8785&lng=102.7420"
   ```
3. **Expected Result**: Response returns `200 OK` with `endpoint` field containing `tmd-radar (kkn240)` or `tmd-radar (skn240)`. No `WARNING: name 'os' is not defined` in server logs.

---

## Step 2: Verify Nong Khai Radar Coverage (tmd_radar_config.py)

**Goal**: Confirm that Nong Khai is now within bounds of both `kkn240` and `skn240`.

1. Run the unit tests:
   ```bash
   cd backend
   ./.venv/bin/pytest tests/test_api_weather.py::test_tmd_radar_bounds_nong_khai -v
   ```
2. **Expected Result**: `PASSED` — confirms Nong Khai is in bounds for `kkn240` and `skn240`, and out of bounds for `kkn120`.

---

## Step 3: Visual Verification of Radar Pin (skn240 crop calibration)

**Goal**: Confirm that pixel mapping for skn240 is accurate after crop calibration.

1. Run the calibration debug script:
   ```bash
   cd backend
   ./.venv/bin/python debug_skn_calibration.py
   ```
2. Open the output image: `backend/tmp/skn240_pin_test.jpg`
3. **Expected Result**:
   - The red crosshair pin should appear north of the **Sakon Nakhon** label on the map.
   - The green `static_crop` box should align closely with the yellow Hough-detected radar circle.

---

## Step 4: Verify CI/CD `CRON_SECRET` Injection (main.yml)

**Goal**: Confirm that `CRON_SECRET` is available in the Cloud Scheduler update step.

1. Trigger a CI/CD pipeline (or review a recent pipeline run in GitLab).
2. In the pipeline log, look for the **"Update Cloud Scheduler Jobs"** step.
3. **Expected Result**: The step runs without `CRON_SECRET: unbound variable` or similar env errors. The scheduler update command completes with exit code 0.

---

## Step 5: Full Run of All Unit Tests

1. Run full test suite:
   ```bash
   cd backend

   ```
