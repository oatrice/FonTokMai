# Architecture Decision Record 009: TMD Radar High-Res Polling & Reliability Architecture (Batch N)

## Context

ปัจจุบันระบบดึงข้อมูลพยากรณ์จาก TMD Radar อาศัยการดาวน์โหลดไฟล์ Loop GIF แบบ 256-color ความละเอียดต่ำ (680x680) มาแตกเป็นเฟรม (T, T-1, ...) ซึ่งมีข้อจำกัดด้านความคมชัด สีสัน และความแม่นยำในการแยกแยะพิกัดเมฆฝน นอกจากนี้ บ่อยครั้งที่ข้อมูลจาก TMD อาจจะขาดหาย (Out of date) หรือเซิร์ฟเวอร์ดีเลย์ ทำให้ระบบส่งการแจ้งเตือนเก่าซ้ำไปให้ผู้ใช้งาน ทำให้ผู้ใช้สับสนเรื่องช่วงเวลาบนภาพ

เพื่อยกระดับความแม่นยำและความน่าเชื่อถือของเรดาร์ จึงได้จัดตั้ง **Batch N: TMD Radar High-Res Polling & Reliability** ซึ่งครอบคลุม 3 Issue ที่เกี่ยวข้องกันในเชิงสถาปัตยกรรมข้อมูล

## Issues in this Batch

การจัดกลุ่ม Issue ทั้ง 3 นี้รวมอยู่ใน Epic หรือ Batch เดียวกัน เนื่องจากมีความเกี่ยวเนื่องกันใน Pipeline การดึงและประมวลผลภาพ:

1. **[#115] [Architecture] Migrate from GIF extraction to Polled Static Frames (T, T-1, T-2, T-3)**
   - **รายละเอียด:** เปลี่ยนผ่านจากสถาปัตยกรรมเดิมที่พึ่งพา Loop GIF มาเป็นการสร้าง Background Worker (Polling) เพื่อดึงภาพ Static High-Res (800x800, True Color) ทุกๆ 5-10 นาที
   - **เหตุผล:** เป็น Core Infrastructure ใหม่ที่จำเป็นต่อการพัฒนาขีดความสามารถการอ่านค่า dBZ และ OCR

2. **[#114] เช็ค timestamp จากภาพเรดาร์ว่า out of date หรือไม่ก่อนประมวลผล**
   - **รายละเอียด:** ใช้ OCR ตรวจสอบ Timestamp จากภาพ (ซึ่งได้ประโยชน์จากความคมชัดของภาพจาก #115) ถ้าระบบพบว่าภาพเกินระยะเวลาที่กำหนด (เช่น ไม่อัปเดตมาแล้ว 30 นาที) ระบบจะ Fallback ทันทีและแจ้งเตือนผู้ใช้งานว่า `ยังไม่มีข้อมูลล่าสุดจากกรมอุตุฯ`
   - **เหตุผล:** ป้องกัน False Positive และลดการทำงานฟรีของระบบหาก TMD ไม่ยอมอัปเดตภาพเรดาร์

3. **[#113] เพิ่ม timestamp +7 IDC สำหรับภาพ Zoom in/Tracking**
   - **รายละเอียด:** นำ Timestamp ที่แกะได้จากข้อ #114 มาแปะ (Stamp) ลงบนมุมภาพ Zoom in/Tracking ให้ผู้ใช้งานเห็นชัดเจน (ใน Timezone `Asia/Bangkok`)
   - **เหตุผล:** สร้าง Transparency ให้ผู้ใช้งานมั่นใจว่าข้อมูลบนแผนที่เป็นของเวลาใด

## Batching Strategy & Implementation Plan (Mitigating Large MR / Complexity)

เพื่อให้การพัฒนาราบรื่น, รีวิวได้ง่าย, และลดความเสี่ยงในการพังของระบบเดิม (Avoid Large MR / Complexity Trap) เราจะไม่ทำทั้ง 3 Issue ใน 1 Merge Request ใหญ่ แต่จะแบ่งเป็น **Phase-based MRs** ตามลำดับดังนี้:

### ✅ MR 1: OCR Validation & Overlay (Issue 114 + 113) - Completed
*เป้าหมาย: สร้างระบบอ่านและประทับเวลาบนโครงสร้างเดิมให้สมบูรณ์ก่อน เพื่อลดความเสี่ยงจากการแตะสถาปัตยกรรมดึงข้อมูล*
- **Overlay:** ดึงโค้ดจาก `WeatherManager` / `TMDRadarProcessor` ที่แกะ Timestamp ได้ มาพิมพ์ข้อความทับลงบนภาพ Zoom in/Tracking ในเวลา +7 IDC (#113)
- **Validation:** ตรวจสอบความเก่าของเวลาที่ OCR แกะได้ หากเกิน 30 นาที จะเพิ่มคำเตือนความแม่นยำต่ำ และหากเกิน 45 นาที จะข้ามการพยากรณ์และแจ้งเตือนผู้ใช้งานว่า `ยังไม่มีข้อมูลล่าสุดจากกรมอุตุฯ` (#114)
- **ประโยชน์:** ทดสอบความแม่นยำของระบบ OCR และการวาด Timestamp บนโปรดักชันได้ทันทีโดยไม่ต้องรอกลไก Polling ใหม่

### ✅ MR 2: High-Res Frame Poller & Architecture Shift (Issue 115) - Completed
*เป้าหมาย: วางโครงสร้างสถาปัตยกรรมใหม่ทับของเดิม เมื่อฟังก์ชันข้างเคียง (OCR & Overlay) พร้อมแล้ว*
- **Polling:** สร้าง Background Worker ยิงขอภาพ Static `latest.png` ทุกๆ 5 นาที
- **Queueing:** ประยุกต์ใช้ OCR จาก MR 1 เพื่อเช็คว่าภาพที่ได้มาใหม่คือเฟรมเวลาถัดไปหรือไม่ หากใช่ให้นำเข้าคิว (Frames Array) บน Cloud Storage/Firestore
- **GIF Fallback:** พัฒนาระบบสำรองฉุกเฉิน (Automated GIF Fallback) หากระบบดึงภาพ Static ไม่ได้เกิน 60 นาที หรือมี Cache น้อยกว่า 2 เฟรม ระบบจะโหลด Loop GIF มาแกะเฟรมแทนโดยอัตโนมัติ (พร้อม Cooldown 30 นาที)
- **Admin Control:** เพิ่มคำสั่ง `/tmd_fallback` บน Telegram เพื่อเปิด-ปิดระบบ Fallback ผ่าน Database ได้ทันที

## Impact & Trade-offs
- **Pros:** 
  - ภาพเรดาร์จะมีความละเอียดสูงขึ้น สีสันสมจริง ลด Noise บนแผนที่
  - ระบบยืดหยุ่นและทนทานต่อการล่มของเซิร์ฟเวอร์กรมอุตุฯ มากขึ้นด้วยการมีทั้ง Static Polling และ GIF Fallback
  - แจ้งเตือนผู้ใช้งานได้อย่างแม่นยำหากฝั่ง TMD ขาดการอัปเดตข้อมูล
- **Cons:** 
  - การพึ่งพา OCR ในทุกรอบ Polling อาจทำให้มี overhead เล็กน้อย (แก้โดยใช้ local `pytesseract` ช่วยลด cost ได้)
  - ระบบ Cache จะซับซ้อนขึ้นเนื่องจากต้องรักษาสถานะคิวหลายเฟรม และต้องรองรับโครงสร้างการเซฟสลับไปมาระหว่าง Static และ GIF
