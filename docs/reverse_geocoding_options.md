# Reverse Geocoding & Location Services 🗺️

เอกสารนี้รวบรวมข้อสรุปจากการวิเคราะห์ทางเลือกในการทำ Reverse Geocoding (แปลงพิกัด Lat, Lng เป็นชื่อสถานที่/ที่อยู่) สำหรับแอปพลิเคชัน FonMaYang เพื่อแสดงชื่อพิกัดให้ผู้ใช้เข้าใจง่าย เช่น หน้าบันทึกพิกัดใหม่ หรือ บนหน้า Map Overview

## 📌 ภาพรวม (Overview)
การทำ Reverse Geocoding จำเป็นต้องใช้ API ภายนอก ซึ่งมีทั้งแบบฟรี และแบบมีค่าใช้จ่าย (แต่มี Free Tier ให้ใช้งาน)

## ⚖️ ทางเลือกของผู้ให้บริการ (API Providers)

| ผู้ให้บริการ | ความแม่นยำในไทย | โควต้าฟรี (Free Tier) | หมายเหตุ |
|---|---|---|---|
| **Google Maps API** | 🌟🌟🌟🌟🌟 (ดีที่สุด) | $200/เดือน (ประมาณ 40,000 requests) | แนะนำที่สุดหากทำแอปใช้งานจริงในไทย ต้องผูกบัตรเครดิต |
| **MapTiler** | 🌟🌟🌟 (ปานกลาง) | 100,000 requests/เดือน | ปัจจุบันโปรเจคใช้ MapTiler เป็นแผนที่ฐาน (Base map) อยู่แล้ว สามารถใช้ Geocoding API ของที่นี่ต่อได้เลย |
| **OpenStreetMap (Nominatim)** | 🌟🌟 (พอใช้) | ฟรี 100% แต่ห้ามใช้ยิง Request หนักๆ | ไม่มีข้อจำกัดเรื่องบัตรเครดิต แต่เหมาะกับหาชื่อถนน/ตำบล มากกว่าชื่อร้านค้าเฉพาะเจาะจง |
| **Mapbox** | 🌟🌟🌟 (ปานกลาง) | 100,000 requests/เดือน | เป็นอีกทางเลือกที่ให้โควต้าฟรีค่อนข้างสูง |

## 💡 ข้อเสนอแนะเชิงสถาปัตยกรรม (Architectural Recommendation)

เพื่อเป็นการประหยัดต้นทุนและทำให้สามารถใช้งาน **Google Maps API** (หรือผู้ให้บริการอื่น) ได้แบบ **"ฟรี"** ในระยะยาว ควรใช้หลักการ **Caching** ดังนี้:

1. **ดึงข้อมูลครั้งเดียวตอนสร้างพิกัด:** เมื่อผู้ใช้ปักหมุดหรือเพิ่มสถานที่ใหม่ (Add New Location) ระบบจะเรียก Geocoding API เพียง 1 ครั้งเพื่อดึงชื่อสถานที่
2. **บันทึกลง Database (Caching):** นำชื่อสถานที่และพิกัดที่ได้ บันทึกลงในฐานข้อมูล (Firestore/Postgres) ทันที
3. **หลีกเลี่ยงการดึงข้อมูลซ้ำ:** เมื่อผู้ใช้เปิดแอป หรือดูหน้า Map Overview ให้แสดงชื่อสถานที่จากฐานข้อมูลของเราเอง **ห้ามเรียก Geocoding API ซ้ำ** ทุกครั้งที่เปิดหน้าจอ

**สรุป:** การใช้เทคนิค Caching จะช่วยให้แอปสามารถรองรับผู้ใช้งานจำนวนมากได้โดยที่จำนวน Request การเรียก Geocoding API แทบจะไม่เกินโควต้าฟรี (40,000 ครั้ง/เดือน) ของ Google เลย
