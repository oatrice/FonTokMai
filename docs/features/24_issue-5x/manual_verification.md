# คู่มือการทดสอบผ่าน DevBot (Manual Verification)

เอกสารนี้รวบรวมขั้นตอนการทดสอบ (Manual Verification) ใน DevBot เพื่อตรวจสอบว่า 2 ปัญหาที่เราเพิ่งแก้ไขไป (Exception String ว่าง และ Open-Meteo ดึงเวลาผิด) ได้รับการแก้ไขอย่างสมบูรณ์

---

## 1. การทดสอบการจัดการ Exception Timeout (ไม่แสดงข้อความว่าง)

เป้าหมาย: เพื่อยืนยันว่าเมื่อ API เกิดการ Timeout หรือเชื่อมต่อไม่ได้ ระบบจะไม่แสดงผลเป็น `❌ ข้อผิดพลาด: Open-Meteo Error: ` (ข้อความว่าง) อีกต่อไป

### วิธีที่ 1: ดูผลจากการใช้งานจริง (Passive)
- รันเซิร์ฟเวอร์ DevBot ตามปกติ
- เมื่อใดก็ตามที่ระบบยิง Request ไปหา `Tomorrow.io` หรือ `Open-Meteo` แล้วเจอปัญหาเน็ตเวิร์คหรือ Rate Limit ระบบจะเปลี่ยนไปแสดงผลเช่น `ConnectTimeout('')` หรือ `ReadTimeout('')` ทันทีแทนที่จะว่างเปล่า

### วิธีที่ 2: จำลองการ Timeout แบบตั้งใจ (Active)
เพื่อให้เห็นภาพชัดเจนที่สุด แนะนำให้แก้โค้ดเพื่อจำลองการเกิด Timeout:

1. เปิดไฟล์ `app/services/open_meteo.py` 
2. ค้นหาบรรทัดที่กำหนด URL (บรรทัดที่ 11) และเปลี่ยน URL ชั่วคราวไปที่ Blackhole IP:
   ```python
   # เดิม: API_URL = "https://api.open-meteo.com/v1/forecast"
   API_URL = "http://10.255.255.1"  # IP ที่ไม่มีอยู่จริง ทำให้เกิด Timeout
   ```
3. ปรับ timeout ให้สั้นลง (บรรทัดที่ 15) เพื่อไม่ต้องรอนาน:
   ```python
   self.timeout = httpx.Timeout(2.0)
   ```
4. Restart เซิร์ฟเวอร์ DevBot
5. เข้า Telegram และพิมพ์คำสั่งขอดูข้อมูลจาก 4 API:
   - หรือกดปุ่ม **"📊 เปรียบเทียบข้อมูล 4 API"**
6. **สิ่งที่คาดหวัง:**
   ระบบจะต้องแสดงผลว่า `❌ ข้อผิดพลาด: Open-Meteo Error: ConnectTimeout('')` หรือ `ReadTimeout` ปรากฏขึ้นมาอย่างชัดเจน ไม่เว้นว่างเปล่า

*(อย่าลืมแก้โค้ดกลับไปเป็น API_URL เดิมหลังการทดสอบครับ)*

## 2. การทดสอบช่วงเวลาพยากรณ์ของ Open-Meteo (ไม่ดึงข้อมูลอดีต)

เป้าหมาย: ตรวจสอบว่า Open-Meteo ดึงข้อมูลของ "ปัจจุบันถึง 3 ชั่วโมงข้างหน้า" ไม่ใช่เอาข้อมูลของ 00:00 - 02:45 UTC มาใช้ตลอดทั้งวัน

### วิธีการทดสอบ
1. เข้า Telegram DevBot
2. พิมพ์คำสั่งเพื่อบังคับเรียก Open-Meteo ตรงๆ โดยใช้ location ปัจจุบันหรือที่ใดก็ได้ เช่น:
   ```
   /rain open-meteo
   ```
3. สังเกตจากผลลัพธ์ที่ได้
   - **กรณีไม่มีฝนตก:** บอทจะตอบว่า `"ยังไม่มีแนวโน้มฝนตกในบริเวณของคุณภายใน 1-2 ชั่วโมงนี้"` 
   - **กรณีมีฝนตก:** บอทจะแสดงกราฟหรือข้อมูลฝนในช่วง 15 นาทีข้างหน้าถึง 3 ชั่วโมงข้างหน้า
4. **การตรวจสอบเชิงลึก (Backend Logs):**
   ให้ดูในหน้าจอ Terminal ที่รัน DevBot อยู่ เมื่อมีการเรียก Open-Meteo จะไม่มี Error เกิดขึ้น และคุณสามารถลองใส่ `print(predictions)` ชั่วคราวในบรรทัดที่ 90 (ใน `open_meteo.py`) ระบบควรพิมพ์ `time` ออกมาเป็นเวลา **ปัจจุบัน** ไปจนถึง **+3 ชั่วโมง** (เช่น ตอนนี้ 12:20 น. ตามเวลาไทย (05:20 UTC) ก้อนข้อมูลแรกควรจะเริ่มต้นที่ราวๆ `2026-06-07T05:15Z` เป็นต้นไป)

## 3. การทดสอบ Tomorrow.io Fallback

เป้าหมาย: ตรวจสอบคำสั่ง `/rain tomorrow home` (หรือสถานที่ใดๆ) ที่ทำให้เกิด Fallback Error Message ก่อนหน้านี้

### วิธีการทดสอบ
1. เข้า Telegram DevBot
2. พิมพ์คำสั่ง:
   ```
   /rain tomorrow home
   ```
3. **สิ่งที่คาดหวัง:**
   - ถ้าระบบ `Tomorrow.io` คืนค่ามาปกติ: บอทต้องบอกสภาพอากาศของ Home โดยอ้างอิงข้อมูลจาก Tomorrow.io 
   - ถ้า `Tomorrow.io` ติด Rate Limit ในรอบนี้: บอทจะเข้าสู่ Fallback และส่งข้อความ `"⚠️ ขออภัย ไม่สามารถเชื่อมต่อกับระบบพยากรณ์ฝนได้ในขณะนี้..."` ตามปกติ ซึ่งยืนยันว่าการทำงานของโหมดบังคับ (Forced mode) ยังถูกต้องตาม Flow ที่ออกแบบไว้
