เพื่อทดสอบการทำงานของ Developer Mock Mode (Issue #19) และทดสอบการทำงานของ Background Scheduler แบบเจาะลึก ผมได้เตรียม **Manual Verification Scenarios** ไว้ 4 สถานการณ์หลักครับ ซึ่งแต่ละอันจะตอบโจทย์และช่วยทดสอบความถูกต้องของระบบในมุมที่แตกต่างกันครับ

> **ข้อกำหนดเบื้องต้น:** คุณต้องตรวจสอบให้แน่ใจว่า `chat_id` ของคุณถูกใส่ไว้ใน `DEVELOPER_CHAT_IDS` ในไฟล์ `.env` แล้ว และตัวแอปพลิเคชันกำลังทำงานอยู่ (`uvicorn app.main:app --port 8001`)

---

### Scenario 1: ทดสอบการพบฝนตกและการแจ้งเตือน (ตอบโจทย์ Issue #19 และการทำงานของ Scheduler)
**จุดประสงค์:** เพื่อยืนยันว่าถ้าระบบตรวจพบฝนตก จะมีการแจ้งเตือนส่งไปยังผู้ใช้จริงๆ
**ขั้นตอน (Steps):**
1. พิมพ์คำสั่งใน Telegram ส่งหาบอท: `/devmock rain`
2. บอทควรจะตอบกลับมาว่า: *"🛠️ [DEV MOCK] เปิดใช้งานโหมดจำลองสถานการณ์: 🌧️ ฝนตกหนัก"*
3. จำลองการทำงานของ Cron job โดยรันคำสั่งใน Terminal:
   ```bash
   curl -X POST http://localhost:8001/api/v1/cron/check-rain -H "X-Cron-Secret: default_secret_for_local_testing"
   ```
4. **ผลลัพธ์ที่คาดหวัง:** บอทจะต้องส่งข้อความแจ้งเตือนมาในแชทว่า *"🌧️ ฝนกำลังตกอยู่ที่พิกัดของคุณ... ความรุนแรง: หนัก (Heavy) คาดว่าจะตกต่อเนื่องประมาณ: 60 นาที"*

---

### Scenario 2: ทดสอบระบบหน่วงเวลา (Cooldown Logic ของ Scheduler)
**จุดประสงค์:** เพื่อยืนยันว่าถ้าระบบเพิ่งแจ้งเตือนฝนตกไปแล้ว จะไม่แจ้งเตือนซ้ำซ้อนจนน่ารำคาญ (ปัจจุบันตั้งค่า Cooldown ไว้ที่ระยะเวลาหนึ่ง)
**ขั้นตอน (Steps):**
1. ในขณะที่ยังอยู่ในโหมด Mock Rain (จาก Scenario 1) ให้รันคำสั่ง Cron job ซ้ำอีกครั้งทันที:
   ```bash
   curl -X POST http://localhost:8001/api/v1/cron/check-rain -H "X-Cron-Secret: default_secret_for_local_testing"
   ```
2. **ผลลัพธ์ที่คาดหวัง:** บอท **ต้องไม่** ส่งข้อความใดๆ เข้ามาใน Telegram (เงียบ) และหากดูในหน้าต่าง Terminal ที่รันแอปพลิเคชันอยู่ จะเห็น Log เขียนว่า `Skipping chat_id <หมายเลขของคุณ> due to cooldown.`

---

### Scenario 3: ทดสอบสถานการณ์ฟ้าโปร่ง (ตอบโจทย์ Issue #19)
**จุดประสงค์:** เพื่อยืนยันว่าหากฝนไม่ตก ระบบจะต้องไม่เกิดการแจ้งเตือนแบบ False Positive
**ขั้นตอน (Steps):**
1. พิมพ์คำสั่งใน Telegram ส่งหาบอท: `/devmock clear`
2. บอทควรจะตอบกลับมาว่า: *"🛠️ [DEV MOCK] เปิดใช้งานโหมดจำลองสถานการณ์: ☀️ ท้องฟ้าแจ่มใส"*
3. (รอให้พ้นช่วง Cooldown หรือแก้ไขฐานข้อมูลให้ last_alerted_at เป็นอดีต) จากนั้นรันคำสั่ง Cron job:
   ```bash
   curl -X POST http://localhost:8001/api/v1/cron/check-rain -H "X-Cron-Secret: default_secret_for_local_testing"
   ```
4. **ผลลัพธ์ที่คาดหวัง:** บอทต้องไม่ส่งข้อความเตือนใดๆ เนื่องจากฝนไม่ตก

---

### Scenario 4: ทดสอบการปิดโหมด Mock (ตอบโจทย์ Issue #19)
**จุดประสงค์:** เพื่อยืนยันว่าการปิดโหมด Mock จะคืนค่าระบบกลับไปเชื่อมต่อกับ Rainbow.ai API ของจริงได้อย่างสมบูรณ์
**ขั้นตอน (Steps):**
1. พิมพ์คำสั่งใน Telegram ส่งหาบอท: `/devmock off`
2. บอทควรจะตอบกลับมาว่า: *"🛠️ [DEV MOCK] ปิดใช้งานโหมดจำลองเรียบร้อยแล้ว"*
3. ลองพิมพ์คำสั่งตรวจสอบเรดาร์แมนนวล เช่น ส่งพิกัดไปให้บอทใหม่ หรือกดปุ่มเช็คฝน
4. **ผลลัพธ์ที่คาดหวัง:** บอทจะตอบกลับข้อมูลโดยดึงสภาพอากาศของจริง ณ ปัจจุบันมาแสดงแทนที่จะเป็นการส่งข้อมูล Mock จากระบบ

สามารถนำ Scenario เหล่านี้ไปกดทดสอบบน Telegram ตามลำดับได้เลยครับ!
