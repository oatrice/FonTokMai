# สรุปการแก้ไขบั๊ก Radar Tracking วงกลมไม่ตรงกลุ่มฝน (Issue 58)

## 🎯 สิ่งที่ดำเนินการ
ผู้ใช้รายงานว่าใน `generate_radar_tracking_image` วงกลมและลูกศรวางตำแหน่งไม่ตรงกับกลุ่มฝน และคาดว่าเกิดจากบั๊กในเรื่อง Coordinate mapping ระหว่างการ Crop และ Upscale

จากการตรวจสอบและทดสอบอย่างละเอียด พบว่า:
1. **คณิตศาสตร์ของ Coordinate Mapping (Crop & Upscale) นั้นถูกต้อง 100%**: การทดสอบด้วยสคริปต์ยืนยันว่าวงกลมที่วาดหลังจากการ Scale ลงบนภาพ จะทับซ้อนกับ pixel เดิมของเมฆก่อนการทำ Scale อย่างสมบูรณ์แบบ
2. **สาเหตุที่แท้จริงคืออัลกอริทึม Clustering**: ฟังก์ชัน `find_approaching_clouds` ใช้อัลกอริทึมจัดกลุ่ม (Clustering) แบบรอบเดียว (Single-pass) โดยจะกวาดหาเมฆที่อยู่ใกล้ขอบ (พิกเซลแรกที่พบ) ในระยะ `cluster_dist` (20 px) 
3. **ผลกระทบ**: กลุ่มเมฆก้อนใหญ่ๆ จะถูกหั่นเป็นกลุ่มเล็กๆ หลายๆ กลุ่ม โดยที่จุดศูนย์กลาง (`cx, cy`) ของกลุ่มเหล่านั้นมักจะไปกระจุกอยู่ตรง "ขอบเมฆ" แทนที่จะเป็นตรงกลางเมฆ ส่งผลให้จุดที่นำมาวาดวงกลมใน `generate_radar_tracking_image` คลาดเคลื่อนและดูเหมือนไม่ได้อยู่บนเมฆจริงๆ 

## 🛠️ การแก้ไขที่นำไปปรับใช้
ปรับปรุงโค้ดใน `app/services/tmd_radar_processor.py` (บรรทัด 436-444):
- เปลี่ยนจาก Single-pass clustering เป็น BFS-based Connected Components
- ใช้ `queue` เพื่อไล่จับพิกเซลทั้งหมดที่เชื่อมต่อกัน (ระยะห่าง < 20 px) แบบต่อเนื่องให้เป็นกลุ่ม (group) เดียวกัน
- ทำให้เมฆฝนทั้งก้อน (แม้จะใหญ่แค่ไหน) ถูกคำนวณรวบเป็น Cluster เดียว
- การคำนวณ Centroid ทีหลังจึงตกอยู่บริเวณ "ศูนย์กลางมวล" (Center of mass) ที่แท้จริงของเมฆก้อนนั้น
- วงกลมและลูกศรจะถูกวาดชี้ไปที่ตรงกลางกลุ่มเมฆอย่างแม่นยำ
