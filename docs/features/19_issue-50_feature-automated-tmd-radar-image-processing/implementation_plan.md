# การดึงข้อมูลและประมวลผลภาพเรดาร์จากกรมอุตุนิยมวิทยา (TMD Radar) (Issue #50)

เป้าหมายของงานนี้คือการดึงภาพเรดาร์จากกรมอุตุนิยมวิทยา (TMD) แบบต่อเนื่อง (Loop) มาประมวลผลเพื่อหาระดับฝนตก (dBZ), **ทิศทาง/ความเร็วในการเคลื่อนที่ของกลุ่มฝน (Motion Prediction)**, และ **การก่อตัว/สลายตัวของเมฆฝน (Growth & Decay)** สำหรับระบบ Hyper-local Nowcasting ตามมาตรฐาน TDD

## การเปรียบเทียบ: Traditional Image Processing vs Vision AI

| คุณสมบัติ | Traditional Image Processing (OpenCV / NumPy) | Vision AI (เช่น Gemini Vision, GPT-4V) |
| :--- | :--- | :--- |
| **ความแม่นยำ (Color mapping)** | **สูงมาก** (ค่าสีตรงตาม RGB เป๊ะ แปลงเป็น dBZ ได้แม่นยำ 100%) | ต่ำ (AI อาจกะประมาณสีได้ ไม่ให้ผลลัพธ์เป็นตัวเลขเป๊ะๆ ทุกครั้ง) |
| **การหาความเร็วและทิศทาง (Motion)** | **ดีเยี่ยม** (ใช้อัลกอริทึม Optical Flow หาเวกเตอร์ความเร็วของพิกเซลเป๊ะๆ) | แย่ (AI ทำงานกับภาพเคลื่อนไหวหรือ Frame ต่อ Frame ได้ช้าและคาดเดายาก) |
| **การก่อตัวและสลายตัว (Growth & Decay)**| **ทำได้ดีเยี่ยม** (นับจำนวนพิกเซลและเทียบระดับ dBZ ระหว่างเฟรมเพื่อคำนวณอัตราการขยาย/หดตัว) | ทำได้ (แต่บอกเป็นสเกลเป๊ะๆ ได้ยาก เช่นบอกไม่ได้ว่าหดตัวลงกี่เปอร์เซ็นต์) |
| **ความเร็วในการประมวลผล (Speed)** | **เร็วมาก** (คำนวณในระดับมิลลิวินาที (ms) ผ่าน Array แบบ Local) | ช้า (ต้องยิง API รอผลเป็นวินาที) |
| **ค่าใช้จ่าย (Cost)** | **ฟรี** (รัน Local CPU) | มีค่าใช้จ่ายต่อ API Call |

> **ข้อสรุป**: ยังคงแนะนำให้ใช้ **OpenCV + NumPy** ครับ เพราะตอบโจทย์เรื่องการคำนวณการสลายตัวและก่อตัวได้อย่างเป็นระบบ ด้วยการใช้ Blob Detection หรือการหา Image Difference ระหว่างเฟรม

## แนวทางและกลยุทธ์ทางเทคนิค

### 1. การดึงภาพแบบต่อเนื่อง (Radar Loop Fetching)
* **เป้าหมาย**: ขอนแก่น (`kkn`, `kknLoop`) และ สกลนคร (`skn120`)
* **กระบวนการ**:
  * ดาวน์โหลดหน้า `loop.php` ของ TMD เพื่อสกัดหาภาพ 3-5 เฟรมล่าสุด (ระยะห่างเฟรมละ 15 นาที) มาเก็บไว้ใน Memory

### 2. การประมวลผลการเคลื่อนที่ การก่อตัว และการสลายตัว
* **Motion (ความเร็วและทิศทาง)**:
  * ใช้เทคนิค **Optical Flow** (`cv2.calcOpticalFlowFarneback`) เพื่อหาทิศทางที่พายุวิ่งไปและความเร็ว (km/h) 
* **Growth & Decay (การก่อตัวและสลายตัว)**:
  * ใช้ **Image Difference / Contour Tracking (Blob Detection)**
  * วัด "ขนาดพื้นที่ (จำนวนพิกเซล)" และ "ความรุนแรง (Average/Max dBZ)" ของกลุ่มฝนที่กำลังพุ่งเป้ามาหาผู้ใช้ ในเฟรมที่ $T-15$ เทียบกับเฟรมปัจจุบัน $T_0$
  * **ก่อตัว (Formation / Growth)**: หากกลุ่มฝนมีขนาดใหญ่ขึ้น หรือ dBZ เข้มขึ้น (พิกเซลสีแดง/ส้ม มีจำนวนเพิ่มขึ้น)
  * **สลายตัว (Dissipation / Decay)**: หากกลุ่มฝนมีขนาดเล็กลง หรือ dBZ อ่อนลง (สีแดงเปลี่ยนเป็นเขียว/เหลือง และขนาดพื้นที่ลดลง)
  * สามารถคำนวณแนวโน้มได้ว่า เมื่อกลุ่มฝนนี้มาถึงผู้ใช้ในอีก $X$ นาทีข้างหน้า มันจะแรงขึ้นหรือสลายตัวไปก่อน

### 3. การคำนวณฝนพุ่งชนเป้าหมาย (Collision & ETA Calculation)
* แปลงพิกัดผู้ใช้ $(Lat_u, Lng_u)$ เป็นพิกเซลเป้าหมาย $(X_u, Y_u)$
* ยิง Ray (Trajectory) สวนทางกับเวกเตอร์การเคลื่อนที่ที่ได้จาก Optical Flow เพื่อหาว่ามีกลุ่มฝนในเส้นทางหรือไม่
* นำอัตราการก่อตัว/สลายตัว มาปรับแก้ค่า dBZ คาดการณ์ (Forecasted dBZ) เมื่อฝนมาถึงพิกัดเป้าหมาย
