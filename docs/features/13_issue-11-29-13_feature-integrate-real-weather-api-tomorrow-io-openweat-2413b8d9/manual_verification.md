# คู่มือการทดสอบระบบแจ้งเตือนฝนแบบแมนนวล (Manual Verification Guide)

คู่มือนี้จัดทำขึ้นเพื่อให้นักพัฒนาสามารถทดสอบการทำงานของระบบพยากรณ์อากาศใหม่ (Tomorrow.io + Fallback) รวมถึงฟีเจอร์การแจ้งเตือนแบบละเอียด (Issues #11, #29, #13, #20, #24) ได้ด้วยตัวเองทีละขั้นตอนอย่างละเอียด

---

## การเตรียมความพร้อมก่อนทดสอบ

**ขั้นตอนที่ 1: ตั้งค่า Environment Variables**
1. เปิดไฟล์ `backend/.env` (หากยังไม่มีให้คัดลอกส่วนที่ขาดจาก `backend/.env.example`)
2. ตรวจสอบให้แน่ใจว่าคุณมีตัวแปร 2 ตัวนี้:
   ```env
   TOMORROW_API_KEY=YOUR_ACTUAL_API_KEY
   RAIN_TRIGGER_THRESHOLD_MM=0.5
   ```
   *(หมายเหตุ: ต้องใส่ API Key ของ Tomorrow.io ของจริงเพื่อทดสอบการเรียกข้อมูลจริง)*

**ขั้นตอนที่ 2: รัน Backend Server**
1. เปิด Terminal ใหม่แล้วเข้าไปที่โฟลเดอร์ `backend/`
2. รันคำสั่งเปิดเซิร์ฟเวอร์ (เช่น ผ่าน uv):
   ```bash
   uv run uvicorn app.main:app --reload
   ```

---

## 🧪 การทดสอบที่ 1: ตรวจสอบการแจ้งเตือนและการใช้ Tomorrow.io

**เป้าหมาย:** ตรวจสอบว่าระบบสามารถอ่านข้อมูลรูปแบบใหม่, คำนวณเวลา, ระยะทาง, และแจ้ง Data Source ถูกต้อง

1. เปิดแอปพลิเคชัน Telegram บนโทรศัพท์หรือคอมพิวเตอร์ของคุณ
2. เข้าไปที่แชทของบอท FonMaYang
3. **(สำคัญมาก)** หากคุณเพิ่งเริ่มใช้งานบอท ให้ส่ง **พิกัด Location** ของคุณให้บอทก่อน เพื่อให้บอทมีข้อมูลพิกัดสำหรับจำลองการพยากรณ์
4. พิมพ์และส่งคำสั่งเพื่อจำลองสถานะฝนตก (Developer Mock Mode):
   ```text
   /devmock rain
   ```
5. **สิ่งที่คาดหวัง (Expected Result):**
   - บอทจะตอบกลับด้วยข้อความแจ้งเตือนทันที
   - ในข้อความจะมีการระบุข้อมูลต่างๆ ครบถ้วน (ตอบโจทย์ Issue #13, #20, #24):
     - ⏰ **เวลาที่เริ่มตก** (แบบระบุชั่วโมง:นาที ควบคู่กับ "ในอีก X นาที")
     - 🛑 **เวลาที่หยุดตก** และระยะเวลาที่ตกต่อเนื่อง (หากเป็นหลักชั่วโมง จะไม่มีคำว่า "0 นาที" ต่อท้าย)
     - 💧 **ความรุนแรง** ของฝน
     - 🌬️ **สภาพลม** (ความเร็ว km/h)
     - 📏 **ระยะห่างจากกลุ่มฝน**
   - บรรทัดสุดท้ายของข้อความ **ต้องระบุแหล่งข้อมูล** เป็น:
     `📡 แหล่งข้อมูล: Tomorrow.io`

---

## 🧪 การทดสอบที่ 2: ทดสอบระบบสำรอง (Fallback Mechanism)

**เป้าหมาย:** ตรวจสอบว่าถ้าระบบ Tomorrow.io พัง ระบบจะสลับไปใช้ Rainbow.ai ให้โดยอัตโนมัติ

1. กลับไปที่ Terminal ที่รัน Backend เซิร์ฟเวอร์ค้างไว้ แล้วกด `Ctrl+C` เพื่อหยุดเซิร์ฟเวอร์
2. เปิดไฟล์ `backend/.env` แล้วทำการ **เปลี่ยนค่า API Key เป็นคำว่า `INVALID_KEY` (พิมพ์ตัวพิมพ์ใหญ่เป๊ะๆ)** เพื่อบังคับให้โหมดจำลองสถานการณ์รู้ว่าเรากำลังแกล้งทำ API พัง
   `TOMORROW_API_KEY=INVALID_KEY`
3. รันเซิร์ฟเวอร์ Backend อีกครั้ง
   ```bash
   uv run uvicorn app.main:app --reload
   ```
4. กลับไปที่แอป Telegram แล้วส่งคำสั่งเดิมอีกครั้ง:
   ```text
   /devmock rain
   ```
5. **สิ่งที่คาดหวัง (Expected Result):**
   - คุณยังคงได้รับข้อความแจ้งเตือนฝนตกอยู่ (แสดงว่าระบบไม่ล่มทั้งหมด)
   - แต่ในบรรทัดสุดท้ายของข้อความ แหล่งข้อมูลจะเปลี่ยนไปเป็น:
     `📡 แหล่งข้อมูล: Rainbow (Local)` หรือ `Rainbow (Global)`
   - ใน Console ของเซิร์ฟเวอร์จะแสดง Warning แจ้งว่าเรียกใช้งาน Tomorrow.io ไม่สำเร็จ

---

## 🧪 การทดสอบที่ 3: ทดสอบตัวกรองฝน (Threshold Filter)

**เป้าหมาย:** ตรวจสอบว่าหากปริมาณฝนต่ำกว่า 0.5 mm/hr ระบบจะไม่ทำการแจ้งเตือนกวนใจผู้ใช้

1. ปิดเซิร์ฟเวอร์ Backend (กด `Ctrl+C`)
2. อย่าลืมนำ `TOMORROW_API_KEY` ที่ถูกต้องกลับมาใส่ใน `backend/.env` ด้วย
3. ไปที่โฟลเดอร์ `backend/tests/` เพื่อจำลองค่า Mock กลับ
   *(เนื่องจากการสั่งผ่าน Telegram /devmock จะล็อกปริมาณฝนไว้ที่ 15.0 mm/hr เราจึงใช้วิธีทดสอบผ่าน Pytest แทน หรือถ้าคุณแก้ไข `test_devmock.py` ให้มีคำสั่งส่งฝนตกปรอยๆ ก็สามารถสั่งทางแชทได้)*
4. ให้เปิด Terminal แล้วรันคำสั่งทดสอบเฉพาะไฟล์ Scheduler:
   ```bash
   uv run pytest tests/test_scheduler.py -v
   ```
5. **สิ่งที่คาดหวัง (Expected Result):**
   - ดูที่ผลของ Test Case `test_check_rain_and_alert_no_rain` หรือ Test Case ที่มีการคืนค่าฝนเท่ากับ `0.1 mm/hr`
   - ระบบ **ต้องไม่** ทำการส่งข้อความ Telegram (Assert `send_telegram_message.assert_not_called()`)
   - ผลการรันเทสต์ควรแสดงสีเขียว (Passed) ทั้งหมด ซึ่งยืนยันได้ว่า Threshold Filter ทำงานได้ถูกต้อง
